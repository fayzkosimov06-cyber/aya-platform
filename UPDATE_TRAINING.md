# Обновление AYA: интерактивное обучение

## Что добавлено

В меню аккаунта появился пункт **«Помощь и обучение»** (`/help/`). Доступны восемь тем: знакомство с AYA, профиль и приватность, мероприятия, волонтёры, рейтинг, уведомления, направления и школы.

После новой выдачи полного доступа через посещения, ручную или массовую выдачу на главной странице показывается приветствие. «Позже» сохраняет паузу. Существующим участникам приветствие принудительно не показывается: они запускают темы из помощи. Кандидатам доступна только тема профиля.

Прогресс сохраняется в аккаунте: тема, версия, состояние, шаг и время изменения. Можно продолжать после нового входа, повторять темы и выходить по Escape. Кнопки обучения не отправляют формы и не записывают на мероприятия. При отсутствии событий, школ или расписания показывается пояснение.

Новых зависимостей нет. Миграция `users/0043_tour_progress.py` добавляет только таблицу прогресса.

## Содержимое ZIP

В папке `django_project` находятся исходники, статика, миграции и тесты. Изменённые и новые файлы перечислены в `CHANGED_FILES_TRAINING.txt`, результаты проверки — в `TEST_REPORT_TRAINING.md`.

**В ZIP намеренно отсутствуют `aya_platform/settings.py`, база данных, `media`, `.env`, `.git`, виртуальное окружение, собранная статика и старые вложенные архивы.** Сохраните эти файлы и папки из вашей установленной версии. Исходные настройки сервера изменять для обучения не нужно; дополнительных context processors или middleware нет.

Основа обновления — переданный вами `django_project.zip`; записанный в нём Git HEAD: `979fb2d5305baa62a60b595919b43c3c37a1e32e`. Удалённая ветка GitHub и текущий сервер не изменялись и не использовались как источник более новой версии. Если после создания исходного ZIP вы меняли код, сравните файлы из списка изменений перед заменой.

## Обновление установленного сайта

1. Сделайте резервную копию работающей базы, пользовательских загрузок и текущего кода. Для SQLite используйте согласованную резервную копию (например, SQLite backup), а не копирование изменяющегося файла базы во время записи.
2. Распакуйте ZIP отдельно. Скопируйте **содержимое** папки `django_project` в каталог проекта с `manage.py`, объединив папки и заменив файлы кода. Не удаляйте существующую папку проекта целиком. Для точечного обновления достаточно новых и изменённых файлов из `CHANGED_FILES_TRAINING.txt`.
3. Откройте Bash-консоль PythonAnywhere, перейдите в каталог **Source code**, указанный на вкладке Web, и активируйте его окружение. В предыдущей конфигурации использовались `/home/AYA1/mysite` и `myenv`; их актуальность на вашем сервере не проверялась. Если они не менялись:

```bash
cd /home/AYA1/mysite
workon myenv
python manage.py check
python manage.py migrate --plan
python manage.py migrate
python manage.py collectstatic --noinput
python manage.py check
```

4. Убедитесь, что миграция применена:

```bash
python manage.py showmigrations users
```

В списке должно быть `[X] 0043_tour_progress`.

5. Нажмите **Reload** на вкладке Web PythonAnywhere. При необходимости обновите страницу браузера с очисткой кэша.

Не запускайте `makemigrations` на сервере для этого обновления: готовая миграция находится в ZIP. Установка пакетов заново не требуется, если окружение уже соответствует `requirements.txt`.

Если обновляете сервер через GitHub, сначала перенесите файлы в свою локальную рабочую копию и отправьте изменения обычным способом. На сервере выполните `git pull` перед командами выше. Не применяйте `reset --hard` для устранения локальных изменений.

## Быстрая проверка после обновления

- Войдите в существующий аккаунт и откройте меню имени → «Помощь и обучение».
- Запустите тему профиля; проверьте «Далее», «Назад» и Escape.
- Продолжите отложенную тему из помощи; обновите страницу посередине темы.
- Откройте обучение мероприятиям. Кнопка «Присоединиться» должна подсвечиваться, но обучение не должно записывать вас.
- Проверьте помощь на телефоне. Существующие участники не должны получать обязательное приветствие.

Выдачу нового доступа и третье посещение проверяйте на тестовой копии с тестовым кандидатом, а не создавая фиктивные посещения в рабочей базе.

## Локальная проверка в отдельной папке

Только для новой тестовой копии, где ещё нет своих настроек:

```powershell
Copy-Item aya_platform/settings.py.example aya_platform/settings.py
python -m pip install -r requirements.txt
python manage.py migrate
python manage.py test --noinput
python manage.py runserver
```

Файл-пример предназначен для локального запуска. Не заменяйте им настройки установленного сервера.

## Если обучение не загружается

Проверьте применение `0043`, выполнение `collectstatic` и Reload. Скрипт загружается из `static/js/training.js`, стили — из `static/css/training.css`; данные прогресса — из `/help/progress/`. Ошибка загрузки обучения не должна закрывать обычные страницы. При конфликте двух вкладок обновите помощь и продолжите с сохранённого шага.

Для отката верните предыдущие версии изменённых файлов кода, выполните `collectstatic` и Reload. Новую таблицу прогресса можно оставить: старый код её не использует. Откат миграции удалит историю обучения, поэтому для обычного отката кода он не нужен.
