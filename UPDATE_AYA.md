# AYA — обновление от 27 сентября 2026

Основа: присланный `aya-platform-main.zip`. Архив содержит совокупное обновление обучения, клубов, профилей, редакторов и исправлений. Сервер и GitHub автоматически не обновлялись.

## Установка на существующий сайт

1. Сохраните резервную копию кода, базы и `media`. При SQLite остановите запись в сайт на время копирования либо используйте штатный SQLite backup.
2. Распакуйте ZIP отдельно. Скопируйте содержимое папки `aya-platform` в каталог проекта рядом с `manage.py`, объединяя папки. Не удаляйте установленный проект целиком.
3. Сохраните серверные `aya_platform/settings.py`, `.env`, базу, пользовательские загрузки и конфигурацию веб-сервера. Их нет в архиве. `settings.py.example` — пример для локальной проверки, не замена рабочих настроек.
4. В окружении сайта из каталога с `manage.py` выполните:

```sh
python configure_controls.py
python manage.py check
python manage.py migrate --noinput
python manage.py collectstatic --noinput
```

5. Перезапустите процесс Django используемым на вашем сервере способом. Обновите страницу браузера с перезагрузкой кэша (Ctrl+F5). Один `collectstatic` не обновляет Python-код в уже запущенном процессе.
6. Проверьте панель модератора, один профиль с датой рождения, назначение и снятие учителя, состав направления и клуба, рамку нескольких должностей, расписание и форму входа сотрудников.

Миграции `users.0044`–`0046` и `events.0012` добавляют клубы и заявки сотрудников, сохраняют материалы после удаления автора и согласуют учителей со школьными назначениями. `migrate` также применит более ранние отсутствующие миграции, включая обучение. Новых библиотек для этих изменений нет.

## Что изменилось

- Единый поиск и выбор без вложенных дубликатов. Отмеченные люди сохраняются при фильтрации; можно показать только выбранных и очистить выбор.
- В списке управления людьми исправлены пропорции фотографий. Должности показываются рядом с именем. Исправлена мобильная раскладка.
- Для учителей — поиск по имени/логину и выбор одного аккаунта, отдельная карточка каждому. Уже назначенные учителя не предлагаются повторно.
- «Снять назначение» сохраняет участие. «Убрать из школы/направления/клуба» снимает членство и назначение в выбранной команде. Данные школы больше не возвращают удалённого участника в направление при обычном сохранении. Независимые назначения в других командах сохраняются.
- Учителя, профильные должности и права согласованы при удалении и смене назначения. При миграции существующие карточки и назначения сохраняются и объединяются. Если в прежней версии снятие оставило старую карточку, снимите такое назначение один раз после обновления: по старым данным нельзя надёжно отличить его от действующего.
- Расписание школ и клубов: будущие, прошлые и отменённые встречи; недельные повторы; редактирование и отмена. Сохранённая прошедшая встреча доступна в соответствующем фильтре.
- Клубы самостоятельные либо связаны с одной школой/направлением. У школы наследуется направление. Несколько ответственных, состав, активная команда, встречи, мероприятия и заявки на баллы.
- Назначения видны в профиле по иерархии. Направление — фиолетовый, учитель — малиновый, клуб — оранжевый. Несколько должностей сочетаются в движущейся рамке. Президент сохраняет золото. Активность — отдельный значок при должности, зелёная рамка только без должностей. При системной настройке уменьшения анимации рамки статичны.
- Исправлено сохранение даты рождения; дата выводится в профилях студентов и сотрудников. Дата регистрации подписана «На сайте с».
- Отдельные профиль, вход `/staff/login/` и регистрация `/staff/signup/` сотрудников. Заявки сотрудников подтверждает начальник или суперадминистратор; заявку начальника — только суперадминистратор. До подтверждения служебных прав и входа нет.
- Журнал сгруппирован по людям, есть история отдельного человека, фильтры и расшифровка изменений. Ссылки и отношения отображаются названиями и именами. История удалённых объектов, где старые записи не сохранили имя, обозначается как удалённая запись. Просмотры/поиски и закрытый журнал доступны только суперадминистратору.
- Удаление аккаунта через сайт с вводом логина и выбором дополнительных материалов. По умолчанию чужие баллы и общие материалы сохраняются; автор обозначается «Аккаунт удалён». Можно отдельно удалить доступные авторские мероприятия, работы и цитаты. Файлы в резервных копиях и неиспользуемые файлы хранилища физически не стираются этим действием.
- Удаление работы полностью убирает её начисления у всех участников. Это отличается от отмены отдельного начисления. Закрытая запись действия сохраняется.
- Кадрирование загружаемых одиночных фото: перемещение, масштаб и предпросмотр. Маленький оригинал не увеличивается искусственно. Уже потерянные детали исходной фотографии восстановить нельзя: для чёткого крупного кадра загрузите оригинал.
- Более компактные цитаты и обновлённые редакторы.
- Обучение по доступным правам: поиск задач, категории, личный прогресс, рекомендация следующей темы, продолжение с сохранённого шага и компактная карточка завершения. Редакторы школ, направлений и клубов имеют последовательные подсказки по вкладкам. Сотрудникам не предлагается личная запись на события как волонтёрам.
- Исправлена ошибка страницы модерации при отсутствующем авторе визита. Проверены границы прав, запреты на повышение себя/равных, работа с чужими объектами и неподтверждённые заявки. Опасные схемы ссылок в профилях блокируются; переходы уведомлений ограничены своим сайтом. Это проверка перечисленных сценариев, а не гарантия отсутствия любых уязвимостей.
- Безопасная пасхалка `/legacy-admin/debug/` показывает «Отдел печенья взломан». Она не выдаёт права, секреты или настоящую административную панель.

## Содержимое и откат

`CHANGED_FILES_AYA.txt` сравнивает код с последним присланным ZIP. `MANIFEST_AYA.json` содержит SHA-256 файлов. `TEST_REPORT_AYA.md` перечисляет проверки; `ROLES_AYA.md` поясняет роли.

Архив не содержит базы, личных фотографий, секретов, тестовых аккаунтов и локальных настроек предпросмотра. Для отката восстановите совместно прежний код и резервную копию базы, сделанную до миграций. Не пытайтесь откатывать только Python-файлы поверх новой базы.
